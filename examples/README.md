# Examples

Everything here is **original synthetic material** written for ExamDNA (introductory physics). Nothing is copied or adapted from any examination board, publisher or past paper.

## `synthetic_inputs/`

| File | What it is |
| --- | --- |
| `paper1.md`, `paper2.md`, `paper3.md` | Three synthetic papers (30, 30, 32 marks; Section A short items, Section B structured) |
| `markscheme_paper1.md` | Marking scheme for paper 1 |
| `syllabus.md` | Miniature syllabus with learning-objective codes |
| `teaching_notes.md` | Accompanying teaching notes |
| `physics_bank.json` | The three papers as a structured bank — what the agent produces after reading the papers |
| `annotations.json` | Genome annotations — the agent's semantic analysis |
| `compile_config.json` | 30-mark exam; requires Kinematics and Electricity |
| `compile_config_harder.json` | Same, with `difficulty_shift: +1` |
| `compile_config_conflict.json` | Deliberately infeasible: requires an `extended_response` item that does not exist |
| `baseline_naive_exam.json` | Illustrative hand-written "unstructured generation" fixture for the evaluation demo (not experimental data) |

`physics_bank.json`, `annotations.json`, the papers and the mark scheme are generated by `tools/build_synthetic_dataset.py` (single source of truth).

### Deliberate problems and expected behaviour

| Item | Problem | Expected |
| --- | --- | --- |
| `p3-a6` (source) | Refers to a diagram that is not supplied; angle and friction missing; no mark-scheme answer | Bank validation: `REVIEW_REQUIRED` (figure not supplied, values not stated) |
| `c04-try1` | Surface mutation that changes a given value | `FAIL preserve:numeric_parameters` |
| `c06-try1` | Parameter mutation that copies the source wording | `FAIL source_copy` and `novelty` (near-duplicate) |
| `c11` | No `target_skill` judgement supplied | `REVIEW_REQUIRED` (excluded from the exam) |
| `c12-try1` | Parameter changed but answer not recomputed | `FAIL recompute` |
| `c14-try1` | Reverse mutation with many valid answers and no accept rule | `FAIL uniqueness` |
| `compile_config_conflict.json` | Unsatisfiable `required_types` | Compilation infeasible; diagnosis with suggestions |

## `expected_outputs/demo_workspace/`

Produced by `python tools/run_demo.py` (deterministic — re-running gives identical files):

- `bank.json`, `genomes.json`, `exam_dna.json`, `mutation_plan.json`, `candidates.json`, `validation_report.json`, `validated_pool.json`, `exam.json`
- `output/` — student exam (`exam.md`, `exam.html`), `answer_key.md`, `marking_guide.md`
- `reports/` — Exam DNA report, validation summary, lineage report, exam-vs-DNA comparison, analysis report
- `extras/` — harder exam, conflict diagnosis, 5-variant plan for `p1-b2`, generation-2 mutation, text-parser ingestion of `paper1.md`, baseline comparison

The candidates in `candidates.json` were written during development by Claude acting as the agent (Stage B) and are stored as fixtures; they are not regenerated by a model when the demo runs.
